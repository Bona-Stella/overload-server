# Overload Statistics and Tracking Design Specification

**버전:** v1.4 · 2026-11-13 근육 집계 후속 개정

**기준일:** 2026-11-13

**상태:** 제품 설계 합의본 · 단계별 구현/검증은 기술 문서 참조  
**연계 문서:** [Overview API](../api/statistics.md) · [현행 주간 일정·일별 검사](../api/weekly-schedule.md) · [디로딩 v1.7](../../../overload-pwa/docs/product/Overload_Deloading_Design_Specification_v1.7.md)

**2026-11-13 후속 확정 / 구현 별도:** [루틴 중심 중량·메모·대체 정책](../../../overload-pwa/docs/product/Overload_UI_Decision_Log_v0.9.md#1021--루틴-중심-중량메모대체-정책--2026-11-13-후속-확정)에 따라 ST-12·18·20·23·38을 보완했다. 대체 슬롯 인정과 오늘만 조합 변경의 공식 평가 전체 제외는 현재 코드에 미연결이며 기존 완료율·근육 집계·G4 산식을 바꾸지 않는다.

**이후 확정된 근육 집계 정책:** 이번 후속 개정은 ST-24~31의 분류별 독립 집계·계획/실제 기여 세트와 선택한 프리셋의 현재 주간 계획 분석을 반영한다. 앞선 루틴 중심 정책과 ST-17~23·DL-08/G4·공식 중량 평가 산식은 유지한다. 실제 세부 근육 기여 일부는 구현되어 있으나 네 분류 수준 전체와 프리셋 계획 분석은 구현 필요다. UI 디자인은 후속 사용자 설계 범위다.

**변경 원칙:** 이 문서를 이후 통계·추적 정책 변경의 기준으로 사용한다. 새 합의는 해당 `ST-XX` 식별자를 유지하여 수정하고 버전·변경 이력을 갱신한다.

> **한눈에 보기**  
> Overload의 통계 및 추적은 **저장된 루틴을 계획의 기준**으로 삼고, **실제 수행 기록을 성과·운동량의 기준**으로 삼는다. 기본 화면에는 이번 주 요약만 간결하게 보여주고, 운동 현황·근육별 통계·성장 추적·운동 이력을 선택하여 상세 조회한다. 계획 외 운동은 기록·운동량 통계에 포함하지만 루틴 달성률에는 영향을 주지 않는다. 디로딩 중 실제 운동은 통계에 포함하되 일반 훈련의 승인 중량 성과 평가에서 제외한다.

## 0. 문서 범위 및 합의 상태

- **[ST-01 · 확정]** 본 문서는 **통계 및 추적 기능 전체**의 1차 제품 설계 기준이다. 근육별 주간 세트만을 별도로 설계한 문서가 아니다.
- **[ST-02 · 확정]** 새 피로도·성장 점수, 루틴 목표 자동 수정, 운동 추천 알고리즘은 만들지 않는다. 기존 운동 데이터와 기존 중량 승인·운동 이력 기능을 우선 재사용한다.
- **[ST-03 · 확정]** 메인 대시보드는 가볍고 직관적으로 유지한다. 세부 차트·표시 방식은 실제 사용 후 필요할 때 개선한다.
- **[ST-04 · 문서 규칙]** **확정**은 사용자와 합의한 기능 정책이다. **구현 확인**은 정책을 바꾸지 않으면서 기존 스키마·API·동기화 흐름을 점검할 사항이다. 새로운 정책이 필요한 경우에는 임의 결정하지 않는다.

## 1. 전체 정보 구조와 화면

### 1.1 기본 대시보드

- **[ST-05 · 확정]** 통계 및 추적의 기본 화면은 **통합 대시보드(A안)**이며, 기본 조회 기간은 **이번 주(월~일)**다.
- **[ST-06 · 확정]** 상단 핵심 요약에는 **계획 운동일 대비 수행, 완료 웨이트 세트, 루틴 달성률**을 간결하게 보여준다. 필요한 경우 유산소 누적 시간 등 요약 정보를 추가하되 한 화면에 전체 차트를 펼치지 않는다.
- **[ST-07 · 확정]** 대시보드에서 **운동 현황 / 근육별 통계 / 성장 추적 / 운동 이력** 상세 화면으로 이동한다. 별도의 최상위 탭들을 항상 띄우는 대신 요약 → 상세 구조를 기본으로 한다.
- **[ST-08 · 확정]** 운동 이력은 메인에 **최근 3건 요약**, `전체 보기`는 기존 운동 이력 화면에 연결한다. 상세 기록·정정·삭제·복구는 기존 기능을 재사용한다.

### 1.2 조회 기간

| 조회 위치 | 기본값·선택 | 표시 원칙 |
|---|---|---|
| 통합 대시보드 | 이번 주(월~일) | 핵심 정보 위주 |
| 주간 상세 | 이전 주 / 다음 주 이동 | 월요일~일요일 고정 |
| 월간 상세 | 월별 조회·비교 | 해당 달 실제 완료량 합계 |
| 성장 추적 | 최근 1개월 / 3개월 / 6개월 / 전체 | 선택 기간의 과거 기록만 조회 |

- **[ST-09 · 확정]** 전체 화면을 한꺼번에 다시 설정하지 않아도 되도록, 기간 변경은 해당 상세 화면에서 처리한다.

## 2. 데이터 원칙: 계획과 실제를 명확하게 구분

- **[ST-10 · 확정] 계획 출처:** 계획 운동일, 계획 운동 종목, 세트 및 유산소 목표는 **기존 저장 루틴**이 기준이다. 운동 시작 시점의 불변 `InitialPlan`을 과거 운동 계획의 기준으로 사용한다. 4.3절의 선택 프리셋 현재 계획 분석은 별도 조회 목적이며 과거 적용 계획·실제 수행·디로딩 임시 계획을 대체하지 않는다.
- **[ST-11 · 확정] 실제 출처:** 실제 수행 세트·중량·반복·유산소 시간·거리·날짜는 유효한 **운동 수행 기록**을 집계한다. 미완료 계획은 수행으로 간주하지 않는다.
- **[ST-12 · 확정] 계획 외 운동:** 세션 InitialPlan에 없는 단순 추가 종목은 실제 운동량·이력에 포함하지만 계획 종목 달성 분자/분모에는 넣지 않는다. ST-18의 인정된 대체는 새 계획 종목을 더하는 대신 연결된 원계획 슬롯의 완료에만 기여한다. 일반 계획 이행률은 ST-17~23을 유지한다. 디로딩은 예정 외 루틴·휴식일의 실제 일반 세션을 자기 InitialPlan으로 평가하여 날짜별 최고 단일 값을 인정하는 별도 정책이다. G4의 현재 구현과 대체 인정 미연결 범위는 기술 문서를 따른다.
- **[ST-13 · 확정] 초과 달성:** 계획 12세트에 실제 15세트를 수행했다면 `15 / 12세트`처럼 그대로 표시한다. **100% 초과를 허용**하며 그래프를 100%로 제한하더라도 수치 자체를 잘라내지 않는다.
- **[ST-14 · 확정] 계획 없음:** 특정 근육의 계획 세트가 0이고 실제 세트가 3이라면 `계획 없음 · 수행 3세트`로 표시한다. 분모 0에 대한 달성률·진행률은 만들지 않는다.
- **[ST-15 · 확정] 즉시 계획과 과거 근거:** 주간 반복 배정과 원본 루틴의 현재 설정은 즉시 바꿀 수 있다. 진행 중 원본 구성/삭제·주간 배정의 실제 변경은 차단하고 승인·no-op은 유지한다. 첫 예정 START의 배정/InitialPlan을 그날 근거로 보존한다. 미시작일은 날짜 종료 직전의 최종 유효 배정을 사용하며 다음 날 변경을 소급하지 않는다. 최초 등록 전 가상 예정일은 생성하지 않는다. 기존 예약 기능은 폐기하고 역사 행만 보존한다.
- **[ST-16 · 확정] 정정 반영:** 수행 기록이 수정·삭제·복구되거나 오프라인 기록이 동기화되면 현재 유효한 기록을 기준으로 해당 기간 통계를 재계산한다. 동기화 날짜를 실제 운동 날짜로 대체하지 않는다.

## 3. 루틴 달성률 및 계획 운동일

### 3.1 하루 종목 완료 기준

- **[ST-17 · 확정]** 하루의 **유효 운동일 = 완료한 계획 운동 종목 수 ÷ 전체 계획 운동 종목 수**. 디로딩 설계의 동일한 공식을 재사용한다. 일일 최대 1.0일.
- **[ST-18 · 확정]** 웨이트는 해당 종목에 계획된 **`InitialPlan` 세트를 모두 수행**해야 종목 완료 1개로 인정한다. 연결된 대체 운동도 전면/후면·PUSH/PULL/LEGS·근육 부위·관리자 순서상 첫 PRIMARY가 모두 정확히 일치하고 원계획 세트 수를 충족하면 원계획 슬롯 완료 1개다. 분류 불일치·누락/불명확한 근거를 임의로 보완하거나 세트 부족을 완료로 처리하지 않는다. 계획 4세트 중 3세트 수행 시 완료 종목으로 계산하지 않지만, **실제 수행한 3세트는 세트 통계에 포함**한다. 대체 인정은 공식 증감 평가 자격과 독립이며 오늘만 조합 변경 세션은 공식 평가 전체 제외다. 세부 조건은 최신 제품 정책 10.21.4절을 따른다.
- **[ST-19 · 확정]** 유산소도 **루틴에 등록된 최초 목표**를 달성해야 계획 종목 완료로 인정한다. 원래 없는 목표를 새로 만들지 않으며, 운동 도중 계획을 낮춰도 `InitialPlan`의 최초 목표를 기준으로 비교한다.
- **[ST-20 · 확정]** 루틴에 없는 단순 추가 운동은 종목 완료 분자·분모에서 제외한다. ST-18의 대체 인정은 연결된 원계획 슬롯을 채우며 분모를 늘리지 않는다. 같은 날 세션이 여러 개여도 하루 유효 운동일은 최대 1이다.
  - **2026-11-02 사용자 확정:** 같은 예정일에 해당 루틴을 여러 번 시작했다면 각 세션의 최초 InitialPlan과 현재 유효 수행을 비교한 **가장 높은 단일 세션 달성률**을 그날의 유효 운동일로 사용한다. 서로 다른 세션의 부분 세트나 완료 종목을 합쳐 새로운 달성률을 만들지 않는다. 예정되지 않은 날의 추가 운동이나 다른 루틴 수행은 계획 달성률을 채우지 않는다.

### 3.2 주간 표시

- **[ST-21 · 확정]** 주간 루틴 달성률은 `월~일 유효 운동일 합계 ÷ 해당 주의 계획 운동일 수 × 100%`를 기본으로 한다. 계획 운동일 수가 양수일 때 적용하며, 상한은 100%다.
- **[ST-22 · 확정]** 대시보드의 계획 운동일 지표는 **루틴 기준**으로 표시한다. 예를 들어 주 4일 계획에서 2일만 온전히 수행하고 하루 추가 유산소를 했다면 `2 / 4일`이다. 부분 수행이 있다면 위 유효 운동일 계산값을 일관되게 사용할 수 있다.
- **[ST-23 · 확정]** 계획 외 단순 추가 운동으로 운동일 지표나 루틴 달성률을 채우지 않는다. ST-18에 따라 인정된 대체만 원계획 슬롯 완료에 반영한다. 추가·대체 운동량은 실제 수행 운동으로 상세 그래프·마일리지·운동 이력에서 확인하며 슬롯 인정량을 별도 수행으로 더하지 않는다.

**예시 — 주 4일 루틴**

| 요일 | 완료 계획 종목 / 전체 | 하루 유효 운동일 |
|---|---|---:|
| 월 | 4 / 4 | 1.00 |
| 화 | 2 / 4 | 0.50 |
| 목 | 3 / 4 | 0.75 |
| 금 | 0 / 4 | 0.00 |
| 합계 | 계획 운동일 4일 | 2.25일 → 주간 달성률 56.25% |

※ 위 지표는 **루틴 이행률**이며, 실제 수행한 총세트나 운동 강도의 대체값이 아니다.

## 4. 근육별 세트 집계

### 4.1 기본 집계

- **[ST-24 · 확정]** 계획과 실제는 독립 원본으로 계산한다. 계획은 계획 세트, 실제는 유효 실제 완료 세트가 원본이다. 전면/후면·PPL·부위 보기는 원본 세트 수, 세부 근육 보기는 ST-25~26의 기여 세트를 사용하며 계획/실제를 구분한다. 실제 참여 세트와 가중 기여 세트도 서로 다른 값이다. 계획 3세트·실제 5세트라면 각 원본은 각각 3·5다.
- **[ST-25 · 확정]** 관리자 표준 운동 DB의 `exercise_muscle`에서 `PRIMARY`로 연결된 각 세부 근육에 원본 1세트당 **1.0 기여 세트**를 반영한다. 복수 PRIMARY도 각 근육에 독립 적용한다. 스쿼트 3세트의 대퇴사두근·둔근이 모두 PRIMARY라면 각각 3.0이며 상위 분류나 전체 세트를 6으로 만들지 않는다.
- **[ST-26 · 확정]** 세부 근육 기여는 **PRIMARY 해당 세트 수 × 1.0 + SECONDARY 해당 세트 수 × 0.5**다. 계획·실제 원본에 각각 적용하며 해당 근육 매핑이 없으면 그 근육 기여는 0이다. 실제 참여 세트의 정수 값·반복·총중량은 0.5로 덮어쓰지 않는다. 0.5는 간접 자극을 훈련량 분석에 반영하는 근사 계수이며 모든 운동의 생리학적 자극이 정확히 절반이라는 의미가 아니다. 운동별 자극 계수 입력·저장은 추가하지 않는다. 조회 시점의 관리자 근육 매핑을 사용한다.
- **[ST-27 · 확정]** **전면/후면, PUSH/PULL/LEGS, 가슴·등·어깨·팔·하체·코어 부위**는 각 분류 수준에서 원본 세트와 검수된 운동 분류를 직접 적용해 독립 집계한다. 동일 원본 세트는 같은 수준의 같은 분류 안에서 한 번만 센다. 복수 PRIMARY·SECONDARY 매핑 수와 무관하며, 하위 기여 세트 합산·역산으로 상위를 만들거나 세부 매핑으로 상위 분류를 추정하지 않는다. 분류 누락·미확정은 임의 보완하지 않고 확인 필요로 구분한다.
- **[ST-28 · 확정]** **전체 실제 완료 세트와 전체 계획 세트**는 근육별 중복과 무관한 원본의 정수 단위다. 실제 완료 세트는 한 번씩만 집계하며 세부 근육 기여 합계로 대체하거나 0.5 단위로 바꾸지 않는다. ST-27의 분류별 값도 다른 수준의 합계가 아니므로 하위 합계와 일치하도록 보정하지 않는다.
- **[ST-29 · 확정]** 계획 외 근력 운동·초과 세트·디로딩 중 실제 수행은 **실제 근육별 통계**에 포함한다. 날짜별 계획은 해당 날짜의 적용 루틴과 ST-10·56을 유지한다. 선택 프리셋의 현재 주간 계획은 4.3절로 별도 계산하며 실제 추가·대체 실적을 그 계획에 더하지 않는다. ST-18의 대체 슬롯 완료 인정도 가상의 수행 세트를 생성하지 않는다.

### 4.2 분석 요구사항과 예시

- **[ST-30 · 확정]** 사용자가 선택한 분류 수준별로 전면/후면·PPL·부위·세부 근육 분석을 제공한다. 계획 분석과 실제 수행 분석의 대상·원본을 구분한다. 기존 화면의 대분류→세부 탐색·PRIMARY 기본·SECONDARY 펼침은 종전 UI 기록이며, 이번 정책으로 새 탭·버튼·드릴다운·차트·레이아웃을 확정하지 않는다. UI는 문서 작업 이후 사용자와 별도로 설계한다.
- **[ST-31 · 확정]** 세부 근육 기여 세트는 소수로 표현하며 역할별 실제 참여 세트와 구별한다. 한 근육의 기여는 ST-26의 식을 따르되 역할 의미를 잃거나 근육 간 합계를 전체 세트·상위 분류·ST-17~23 루틴 달성률로 표시하지 않는다.

**예시 — 검수된 스쿼트 분류가 전면 / LEGS / 하체이고 대퇴사두근 PRIMARY·햄스트링 SECONDARY인 경우**

| 보기·단위 | 원본 1세트 | 원본 4세트 |
|---|---:|---:|
| 전면/후면 · 전면 | 1 | 4 |
| PPL · LEGS | 1 | 4 |
| 부위 · 하체 | 1 | 4 |
| 세부 대퇴사두근 기여 | 1.0 | 4.0 |
| 세부 햄스트링 기여 | 0.5 | 2.0 |
| 물리적 전체 세트 | 1 | 4 |

세부 기여 합 1.5 또는 6.0을 상위나 전체 세트로 사용하지 않는다. 실제 SECONDARY 참여 세트가 4라면 참여는 4, 기여는 2.0이다. 동일 운동에 PRIMARY가 여러 개여도 각 PRIMARY의 1.0 기여와 상위/전체 원본 1세트를 분리한다. 이 예시는 실제 카탈로그의 운동 분류를 새로 확정하는 데이터가 아니다.

### 4.3 선택한 주간 프리셋의 현재 계획 분석

사용자가 조회·선택한 프리셋의 월~일 배정과 배정된 **현재 저장 루틴의 계획 세트**를 사용한다. 활성 프리셋뿐 아니라 다른 프리셋도 분석할 수 있다. 같은 루틴이 월·목에 배정되면 두 날짜의 계획을 각각 포함한다. 프리셋에는 기존 루틴 배정만 두며 운동 구성·중량·분석용 계획을 중복 저장하지 않는다.

각 요일의 원본 계획 세트에서 ST-24~28의 네 수준을 독립 계산한다. 위 스쿼트가 월요일 4세트·목요일 4세트라면 원본 주간 계획은 8세트, 전면 8 / LEGS 8 / 하체 8 / 대퇴사두근 기여 8.0 / 햄스트링 기여 4.0이다.

이는 **선택 프리셋의 현재 계획 분석**이며 특정 과거 주의 실제 적용 프리셋 이력 통계, 실제 완료량, 디로딩 감량 임시 계획과 구분한다. 과거 날짜의 계획·수행·루틴 달성률과 G4 유효 운동일을 현재 선택으로 다시 계산하지 않는다. 정책은 확정했으나 전용 조회·계획 기여·네 수준 전체 지원은 구현 필요다. API 경로·DTO와 UI 디자인은 이 절에서 확정하지 않는다.

## 5. 운동별·근육별 총중량과 추적

- **[ST-32 · 확정]** 운동별·근육별로 **완료 세트 수와 총중량**을 확인한다. 주간·월간 비교 모두 지원한다.
- **[ST-33 · 확정]** **총중량(kg) = Σ(각 완료 세트의 실제 사용 중량[kg] × 해당 세트의 실제 완료 반복 횟수)**. 반복 횟수를 빼고 중량만 더하지 않는다. 예: **80kg × 10회 + 80kg × 8회 + 70kg × 10회 = 2,140kg**. 세트별 실제 기록을 사용하며, 계획 반복 횟수를 대신 곱하지 않는다.
- **[ST-34 · 확정]** 이 문서의 **총중량**은 일반적으로 **볼륨 로드(중량 × 반복 횟수의 합)**라고 부르는 지표다. 별도 `세트 중량 단순 합`을 총중량으로 표기하지 않는다. 이는 승인 중량 성장 추적 지표와도 구분한다.
- **[ST-35 · 확정]** 근육별 총중량에도 주동근별 전체 반영, 대분류 동일 세트 중복 제거, 전체 운동 중복 제거 원칙을 동일하게 적용한다. 하나의 실제 세트를 같은 대분류에서 여러 번 더하지 않는다.
- **[ST-36 · 확정]** 맨몸 운동처럼 중량이 없는 경우 **총중량 항목을 표시하지 않는다**. 세트·반복은 정상 표시한다. **추가 중량이 명시적으로 기록된 경우에는 기록된 추가 중량 × 반복 횟수만 합산**하고, 체중을 임의 환산하지 않는다. 기존 기록 구조에서 추가 중량을 별도로 식별할 수 있는지 구현 시 확인한다.
- **[ST-37 · 확정]** 상세 그래프는 **세트 수 ↔ 총중량**을 선택하여 전환하는 **동일한 재사용 UI**를 운동별·근육별 화면에 적용한다. 맨몸 또는 중량 데이터가 없는 종목은 총중량 전환 항목을 숨긴다.

## 6. 운동별 성장 추적

- **[ST-38 · 확정]** 운동별 성장 추적의 **기본 그래프는 기존 루틴 배치별 승인 중량의 시간 변화**를 사용한다. 실제 수행한 중량·세트·반복 횟수와 조합 재선택 제안값은 승인 성장선이 아니다. 조합 변경 저장은 기존 배치 제외+NEW로 새 기준을 시작하고 같은 조합 복귀도 옛 배치 benchmark·승인 성장선을 새 배치에 연결하지 않는다. 최초 운동부터 기존 권고 조건을 적용하며 유예 기간은 없다. 실제 수행 기록은 별도로 유지한다.
- **[ST-39 · 확정]** 현재 루틴에 등록된 운동만으로 제한하지 않고, **선택한 조회 기간의 전체 과거 운동 기록**에서 종목을 선택한다. 현재 루틴에서 삭제된 종목도 과거 기록이 있다면 조회 가능하다.
- **[ST-40 · 확정]** 운동 종목을 **검색으로 선택**하며 **최근 수행 종목 우선**으로 보여준다. 선택 기간에 해당하는 데이터만 그래프에 반영한다.
- **[ST-41 · 확정]** 디로딩 수행 중량은 운동 이력 및 운동량 통계에 포함하지만 **일반 중량 승인·증량·유지·감량 성과 평가 및 승인 중량 성장선에서는 제외**한다. 기존 중량 평가 체계를 새로 정의하지 않는다.
- **[ST-42 · 확정]** 승인 중량이 없거나 선택 기간에 해당 기록이 없다면 수치를 만들어내지 않고 데이터가 없음을 표시한다.

## 7. 주간·월간 운동량 추이

- **[ST-43 · 확정]** 주간 운동량은 **월~일 실제 완료 세트 합계**, 월간 운동량은 **해당 월 실제 완료 세트 합계**로 표시한다. 새 점수·정규화·피로도 추정은 하지 않는다.
- **[ST-44 · 확정]** 주간·월간 상세에서 **전체, 운동 종목별, 근육별** 실제 세트 수·총중량을 선택해 조회할 수 있다. 통합 화면에서는 요약만 제공한다.
- **[ST-45 · 확정]** 디로딩 기간이 포함된 주·월에는 그래프에 작은 **`디로딩` 표시**를 붙인다. 디로딩 중 수행 세트도 실제 통계 합계에 포함한다. 운동량 감소를 자동으로 부정적 평가하지 않는다.
- **[ST-46 · 확정]** 월마다 일수가 달라도 보정하지 않고 해당 월의 **실제 누적량**을 표시한다. 주간 평균으로 환산한 새 지표는 이번 버전의 필수 기능이 아니다.

## 8. 유산소 통계 및 마일리지

- **[ST-47 · 확정]** 유산소는 **근육별 웨이트 세트 통계에 포함하지 않고**, **운동 시간과 거리 중심의 별도 통계**로 표시한다. 단, 루틴에 포함된 유산소는 루틴 종목 달성률에는 포함한다.
- **[ST-48 · 확정]** 유산소 전체 **주간 누적 운동 시간**을 합산한다. 상세에서 월간 누적 시간도 확인할 수 있다. 계획 시간이 존재하면 **실제 시간 / 계획 시간**도 보여준다.
- **[ST-49 · 확정]** 유산소 **주간·월간 누적 거리**를 보여주되, 달리기와 실내 자전거처럼 **운동 종류별 거리로 구분**한다. 서로 다른 운동 종류의 거리를 하나의 총 km로 합쳐 성과 지표로 제시하지 않는다.
- **[ST-50 · 확정]** 직접 입력한 **실제 거리**가 있으면 그 값을 우선한다. 거리는 없지만 **실제 운동 속도와 운동 시간**을 알 수 있다면 `거리(km) = 속도(km/h) × 시간(분)/60`으로 자동 계산해 누적 마일리지에 반영한다.
- **[ST-51 · 확정]** 자동 산출 거리는 사용자가 실제 기록과 구별할 수 있도록 **`계산 거리`**로 표시하고 수정할 수 있게 한다. 수정한 거리에는 자동 계산값을 다시 덮어쓰지 않는다. 속도 또는 시간이 부족하면 거리를 억지로 추정하지 않고 시간만 반영한다.
- **[ST-52 · 확정]** 계획 외 유산소와 디로딩 유산소도 **실제 누적 시간·거리**에 포함한다. 다만 계획 외 유산소는 원본 루틴 달성률에 영향을 주지 않는다.

**예시 — 러닝머신 8km/h, 30분, 거리 미입력**

`8 × (30 ÷ 60) = 4.0km` → 운동 기록에 계산 거리 4.0km 반영. 이후 사용자가 3.8km로 수정하면 **3.8km가 우선**한다.

## 9. 날짜·이력·디로딩 연동

- **[ST-53 · 확정] 운동 날짜 귀속:** **운동 세션의 시작 시간에 해당하는 날짜**에 모든 수행 기록을 귀속한다. 자정을 넘어 종료해도 하나의 세션을 두 날짜로 분할하지 않는다. 일요일에 시작한 운동은 월요일 새벽에 끝나도 일요일 주간 통계에 들어간다.
- **[ST-54 · 확정] 시간 제한 없음:** 자정~새벽 4시 등 특정 시간대에 운동 시작·세트 기록·종료를 제한하지 않는다.
- **[ST-55 · 확정] 이력 재사용:** 통계에서 운동 내역을 누르면 기존 운동 이력 상세로 연결한다. 기존 수행 기록의 정정·삭제·복구 및 오프라인 동기화 결과를 통계에 반영한다.
- **[ST-56 · 확정] 디로딩 계획 비교:** 디로딩 중에는 **디로딩 임시 루틴의 계획 세트**를 분모로 사용한다. 디로딩이 아닌 날은 해당 날짜의 **일반 루틴 계획**을 사용한다. 한 주에 두 기간이 섞이면 각 날짜의 적용 계획을 합산한다.
- **[ST-57 · 확정] 평가 분리:** 디로딩 운동은 이력·근육별 실제 세트·월간 추이·유산소 마일리지에 포함하지만 **일반 승인 중량 변화에 대한 성과 평가에서는 제외**한다. 원본 루틴 및 승인 중량을 변경하지 않는다.

## 10. 구현 연계와 기술 확인 사항

다음은 새로운 제품 정책이 아니라 **기존 코드와 데이터 구조에 맞춰 구현 전에 검증할 항목**이다.

| 확인 항목 | 개발에서 확인할 내용 |
|---|---|
| 기존 운동 계획 | `InitialPlan`과 적용 시점별 루틴 계획 버전으로 과거 계획을 재현할 수 있는 범위. **운동을 시작하지 않은 과거 예정일**까지 당시 계획을 보존하는지 확인 필요 |
| 세트 수행 상태 | 실제 완료 세트, **세트별 실제 반복 횟수·중량**(총중량 산출), 미완료·무수행 세션, FINISHED/AUTO_CLOSED 및 사후 수정·삭제·복구 기록의 집계 기준 연결 |
| 운동 날짜 | 세션 시작 타임스탬프와 저장된 운동 날짜의 일치, 자정 넘김, 오프라인 업로드 날짜와 실제 운동 날짜 구분 |
| 표준 운동 매핑 | `standardExerciseId`, `exercise_muscle`의 `PRIMARY` / `SECONDARY`, 세부 `muscle`·`group_code`가 정확한지 검증. 중복 근육 매핑을 중복 집계하지 않도록 처리 |
| 네 수준 독립 집계 | 운동의 검수된 전면/후면·PPL·부위 분류 조회 근거를 확인한다. 현재 근육 `group_code` 매핑을 운동의 직접 부위 분류로 임의 대체하지 않는다. 누락/미확정의 표시 계약과 계획·실제 기여의 소수 표현은 구현 확인 |
| 선택 프리셋 계획 | 현재 프리셋 조회와 배정 루틴을 재사용하여 월~일 출현별 계획을 읽는다. 기존 `PlanningCalculator`의 과거 날짜 근거와 분리하고 새 HTTP/DTO는 후속 계약으로 정한다. 현재 구현 차이는 [통계 API](../api/statistics.md#분류별-독립-집계와-선택-프리셋-계획--2026-11-13)를 따른다 |
| 성장 추적 | 승인 중량의 변경 이력·시점 조회 가능 여부와 현재 운동 정의/삭제된 루틴의 과거 종목 조회 확인 |
| 유산소 기록 | 실제 시간·속도·거리 단위와 저장 경로, `계산 거리`의 출처 구분, 수정 후 자동값 덮어쓰기 방지 가능 여부 |
| 맨몸·추가 중량 | `BODYWEIGHT`와 별도 추가 부하의 기록 방식. 체중을 임의로 산출하지 않고 표시 여부 결정 |
| 디로딩 연결 | 디로딩 기간 구분, 임시 루틴 계획 참조, 정상 승인 중량 평가 제외, 10일 자동 완료 후 이력 유지 |
| 조회/성능 | 주간·월간·기간별 서버 집계/API 재사용 가능성과 오프라인 미동기화 상태 UI의 표시 정확성 |

**구현 원칙:** 이미 존재하는 조회 API·운동 이력·중량 승인·오프라인 기록 흐름을 먼저 점검한다. 새 스키마·배치·별도 집계 테이블은 필요성이 실제로 확인되는 경우에만 도입한다. 이 문서는 API 명세나 구현 완료 보고서를 대체하지 않는다.

00시는 날짜 경계, 다음 날04시는 미수행 검사 시각이다. 실제 수행 없는 예정일만 별도 MISS를 보존하고 휴식일마다 REST 행을 만들지 않는다. ACTIVE/근거 부족은 보류한다. 실제 부분 수행·다른 일반 루틴·휴식일 수행도 실제 기록으로 남기며 늦은 확정·정정·삭제·명시 복구는 같은 날짜를 재평가한다. 최초 MISS는 삭제/변조하지 않고 현재 유효 상태를 원본으로 해석한다. 같은 날짜를 중복 집계하거나 세션 부분을 합성하지 않는다.

T02-B 단일 일정 구현 당시에는 UI v0.9의 시각 구조를 유지하면서 현재 assignments/version/appliedAt으로 홈·루틴 일정을 연결한다. current/pending/nextEffectiveFrom 및 예약 표시·적용일 선택을 소비하지 않는다. 신규 프리셋의 요청·응답은 [현행 API](../api/weekly-schedule.md), 화면은 [UI 결정 10.16절](../../../overload-pwa/docs/product/Overload_UI_Decision_Log_v0.9.md#1016--다중-주간-루틴-일정과-자동-순환)을 따른다. 저장 뒤 현재값을 재조회하고 교체 확인·루틴 부분 성공·실패 입력을 유지한다. 검사 전 미수행을 확정 표시하지 않고 진행/검사 대기를 구분한다. 기존 HTML/Decision Log v0.9의 다음 월요일 문구는 이 후속 계약이 대체한다. 원래 역사 문서는 덮어쓰지 않는다.

디로딩은 월~일, 서로 다른 실제 수행·미수행 평가 날짜의 E/N, E≤1 누적 초기화, 다음 월요일04시 이후 확정, OFF/epoch·기간 정지·완료/취소 보존이라는 승인 정책을 따른다. **이 절 작성 당시에는 분석·주별 누적·실제 기간이 구현 전이었다.** 현재 상태는 아래 프리셋 연동 절을 참고한다. UI의 개발용 게이지는 실제 누적값이 아니다. 실제 적용은 [API 계약](../api/weekly-schedule.md) 및 별도 DB 승인 범위를 따른다.

### 2026-11-07 참조 정정 (당시 기록)

## 일반 운동 종료 권고와 공식 평가의 적용 구분 — 2026-11-13

사용자가 미완료 세트 감량은 화면 권고만 바꾸고 공식 기준 기록 자격은 유지하도록 확정했다. [세션 API의 weightReview](../api/workout-sessions.md#종료-화면의-중량-검토-권고--공식-평가와-분리)는 종료 화면 사용자 안내이며 공식 completionAssessment/currentAssessment와 다른 결과다. 정상 승인 문맥의 미완료는 DECREASE 권고가 가능하지만 전체 원계획 미완료는 기존 공식 자격에서 제외된다. 자동 승인 중량 변경·성장 사건 생성·벤치마크 승격을 하지 않는다. 진행 중 progress-assessment도 잠정 안내이며 공식 종료 평가를 봉인하지 않는다.

정확한 첫 N개/승인 문맥/기여 세트·nullable/version 계약은 위 API가 소유한다. UI는 유지 항목을 권고 목록에서 제외하고 증량의 해당 반복·하한 미달 반복·미완료 세트 수만 강조한다. 기존 수행 볼륨·통계·공식 승인 사건의 정책과 최초 평가 보존을 변경하지 않는다. Backend a56103e에서 구현했으며 스키마 변경은 없다.
