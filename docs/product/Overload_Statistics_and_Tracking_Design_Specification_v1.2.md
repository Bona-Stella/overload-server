# Overload Statistics and Tracking Design Specification

> **역사 자료.** 현재 일반 통계는 [v1.4](Overload_Statistics_and_Tracking_Design_Specification_v1.4.md)와 [Overview API](../api/statistics.md), 일정 적용·순환은 [주간 일정 API](../api/weekly-schedule.md)를 따른다.

**버전:** v1.2  
**기준일:** 2026-11-02  
**상태:** 제품 설계 합의본 · 단계별 구현/검증은 기술 문서 참조  
**연계 문서:** [Overload Deloading Design Specification v1.2](Overload_Deloading_Design_Specification_v1.2.md)
**변경 원칙:** 이 문서를 이후 통계·추적 정책 변경의 기준으로 사용한다. 새 합의는 해당 `ST-XX` 식별자를 유지하여 수정하고 버전·변경 이력을 갱신한다.

> **한눈에 보기**  
> Overload의 통계 및 추적은 **저장된 루틴을 계획의 기준**으로 삼고, **실제 수행 기록을 성과·운동량의 기준**으로 삼는다. 기본 화면에는 이번 주 요약만 간결하게 보여주고, 운동 현황·근육별 통계·성장 추적·운동 이력을 선택하여 상세 조회한다. 계획 외 운동은 기록·운동량 통계에 포함하지만 루틴 달성률에는 영향을 주지 않는다. 디로딩 중 실제 운동은 통계에 포함하되 일반 훈련의 승인 중량 성과 평가에서 제외한다.

## 0. 문서 범위 및 합의 상태

- **[ST-01 · 확정]** 본 문서는 **통계 및 추적 기능 전체**의 1차 제품 설계 기준이다. 근육별 주간 세트만을 별도로 설계한 문서가 아니다.
- **[ST-02 · 확정]** 새 피로도·성장 점수, 루틴 목표 자동 수정, 운동 추천 알고리즘은 만들지 않는다. 기존 운동 데이터와 기존 중량 승인·운동 이력 기능을 우선 재사용한다.
- **[ST-03 · 확정]** 메인 대시보드는 가볍고 직관적으로 유지한다. 세부 차트·표시 방식은 실제 사용 후 필요할 때 개선한다.
- **[ST-04 · 문서 규칙]** **확정**은 사용자와 합의한 기능 정책이다. **구현 확인**은 정책을 바꾸지 않으면서 기존 스키마·API·동기화 흐름을 점검할 사항이다. 새로운 정책이 필요한 경우에는 임의 결정하지 않는다.

## 1. 전체 정보 구조와 화면

### 1.1 기본 대시보드

- **[ST-05 · 확정]** 통계 및 추적의 기본 화면은 **통합 대시보드(A안)**이며, 기본 조회 기간은 **이번 주(월~일)**다.
- **[ST-06 · 확정]** 상단 핵심 요약에는 **계획 운동일 대비 수행, 완료 웨이트 세트, 루틴 달성률**을 간결하게 보여준다. 필요한 경우 유산소 누적 시간 등 요약 정보를 추가하되 한 화면에 전체 차트를 펼치지 않는다.
- **[ST-07 · 확정]** 대시보드에서 **운동 현황 / 근육별 통계 / 성장 추적 / 운동 이력** 상세 화면으로 이동한다. 별도의 최상위 탭들을 항상 띄우는 대신 요약 → 상세 구조를 기본으로 한다.
- **[ST-08 · 확정]** 운동 이력은 메인에 **최근 3건 요약**, `전체 보기`는 기존 운동 이력 화면에 연결한다. 상세 기록·정정·삭제·복구는 기존 기능을 재사용한다.

### 1.2 조회 기간

| 조회 위치 | 기본값·선택 | 표시 원칙 |
|---|---|---|
| 통합 대시보드 | 이번 주(월~일) | 핵심 정보 위주 |
| 주간 상세 | 이전 주 / 다음 주 이동 | 월요일~일요일 고정 |
| 월간 상세 | 월별 조회·비교 | 해당 달 실제 완료량 합계 |
| 성장 추적 | 최근 1개월 / 3개월 / 6개월 / 전체 | 선택 기간의 과거 기록만 조회 |

- **[ST-09 · 확정]** 전체 화면을 한꺼번에 다시 설정하지 않아도 되도록, 기간 변경은 해당 상세 화면에서 처리한다.

## 2. 데이터 원칙: 계획과 실제를 명확하게 구분

- **[ST-10 · 확정] 계획 출처:** 계획 운동일, 계획 운동 종목, 세트 및 유산소 목표는 **기존 저장 루틴**이 기준이다. 운동 시작 시점의 불변 `InitialPlan`을 과거 운동 계획의 기준으로 사용한다.
- **[ST-11 · 확정] 실제 출처:** 실제 수행 세트·중량·반복·유산소 시간·거리·날짜는 유효한 **운동 수행 기록**을 집계한다. 미완료 계획은 수행으로 간주하지 않는다.
- **[ST-12 · 확정] 계획 외 운동:** 루틴에 없는 추가 웨이트·유산소는 **실제 운동량, 운동 이력, 상세 추적**에 포함하지만 **계획 운동일과 루틴 달성률, 디로딩 유효 훈련 주수**에는 포함하지 않는다. 원본 루틴 목표도 변경하지 않는다.
- **[ST-13 · 확정] 초과 달성:** 계획 12세트에 실제 15세트를 수행했다면 `15 / 12세트`처럼 그대로 표시한다. **100% 초과를 허용**하며 그래프를 100%로 제한하더라도 수치 자체를 잘라내지 않는다.
- **[ST-14 · 확정] 계획 없음:** 특정 근육의 계획 세트가 0이고 실제 세트가 3이라면 `계획 없음 · 수행 3세트`로 표시한다. 분모 0에 대한 달성률·진행률은 만들지 않는다.
- **[ST-15 · 확정] 당시 계획 보존:** 주중 원본 루틴을 수정해도 이미 지난 운동의 계획·실제 기록을 소급 변경하지 않는다. 수정된 루틴은 이후 운동일부터 적용한다. 한 주에 계획 버전이 혼재하면 **각 운동일 당시 적용 계획**을 기준으로 집계한다.
  - **2026-11-02 사용자 확정:** 주간 일정의 **최초 등록과 요일·빈도 변경은 다음 월요일부터** 적용한다. 기록이 없는 과거 일정은 생성하지 않는다. 기존 루틴의 종목·세트 변경과 시작한 운동의 불변 InitialPlan 보존은 위 원칙을 유지한다.
- **[ST-16 · 확정] 정정 반영:** 수행 기록이 수정·삭제·복구되거나 오프라인 기록이 동기화되면 현재 유효한 기록을 기준으로 해당 기간 통계를 재계산한다. 동기화 날짜를 실제 운동 날짜로 대체하지 않는다.

## 3. 루틴 달성률 및 계획 운동일

### 3.1 하루 종목 완료 기준

- **[ST-17 · 확정]** 하루의 **유효 운동일 = 완료한 계획 운동 종목 수 ÷ 전체 계획 운동 종목 수**. 디로딩 설계의 동일한 공식을 재사용한다. 일일 최대 1.0일.
- **[ST-18 · 확정]** 웨이트는 해당 종목에 계획된 **`InitialPlan` 세트를 모두 수행**해야 종목 완료 1개로 인정한다. 계획 4세트 중 3세트 수행 시 완료 종목으로 계산하지 않지만, **실제 수행한 3세트는 세트 통계에 포함**한다.
- **[ST-19 · 확정]** 유산소도 **루틴에 등록된 최초 목표**를 달성해야 계획 종목 완료로 인정한다. 원래 없는 목표를 새로 만들지 않으며, 운동 도중 계획을 낮춰도 `InitialPlan`의 최초 목표를 기준으로 비교한다.
- **[ST-20 · 확정]** 루틴에 없는 추가 운동은 종목 완료 분자·분모에서 제외하며, 같은 날 세션이 여러 개여도 하루 유효 운동일은 최대 1이다.
  - **2026-11-02 사용자 확정:** 같은 예정일에 해당 루틴을 여러 번 시작했다면 각 세션의 최초 InitialPlan과 현재 유효 수행을 비교한 **가장 높은 단일 세션 달성률**을 그날의 유효 운동일로 사용한다. 서로 다른 세션의 부분 세트나 완료 종목을 합쳐 새로운 달성률을 만들지 않는다. 예정되지 않은 날의 추가 운동이나 다른 루틴 수행은 계획 달성률을 채우지 않는다.

### 3.2 주간 표시

- **[ST-21 · 확정]** 주간 루틴 달성률은 `월~일 유효 운동일 합계 ÷ 해당 주의 계획 운동일 수 × 100%`를 기본으로 한다. 계획 운동일 수가 양수일 때 적용하며, 상한은 100%다.
- **[ST-22 · 확정]** 대시보드의 계획 운동일 지표는 **루틴 기준**으로 표시한다. 예를 들어 주 4일 계획에서 2일만 온전히 수행하고 하루 추가 유산소를 했다면 `2 / 4일`이다. 부분 수행이 있다면 위 유효 운동일 계산값을 일관되게 사용할 수 있다.
- **[ST-23 · 확정]** 계획 외 운동으로 운동일 지표나 루틴 달성률을 채우지 않는다. 추가 운동은 상세 그래프·마일리지·운동 이력에서 확인한다.

**예시 — 주 4일 루틴**

| 요일 | 완료 계획 종목 / 전체 | 하루 유효 운동일 |
|---|---|---:|
| 월 | 4 / 4 | 1.00 |
| 화 | 2 / 4 | 0.50 |
| 목 | 3 / 4 | 0.75 |
| 금 | 0 / 4 | 0.00 |
| 합계 | 계획 운동일 4일 | 2.25일 → 주간 달성률 56.25% |

※ 위 지표는 **루틴 이행률**이며, 실제 수행한 총세트나 운동 강도의 대체값이 아니다.

## 4. 근육별 세트 집계

### 4.1 기본 집계

- **[ST-24 · 확정]** 근육별 주간 통계는 **계획 세트 / 실제 완료 세트**를 같이 보여준다. 예: `가슴 8 / 12세트`.
- **[ST-25 · 확정]** `exercise_muscle`에서 `PRIMARY`로 연결된 **세부 주동근별로 해당 운동 세트를 전부 반영**한다. 예: 스쿼트 3세트가 대퇴사두근·둔근 모두 `PRIMARY`라면 각각 3세트.
- **[ST-26 · 확정]** `SECONDARY` 보조근 참여 세트는 **주동근과 별도 집계**하며 상세 화면에서 참고 정보로 보여준다. 주동근 세트에 합산하거나 임의의 비율(0.5세트 등)로 환산하지 않는다.
- **[ST-27 · 확정]** 가슴·등·어깨·팔·하체·코어 같은 **대분류 합계**에서는 같은 실제 세트가 대분류 안의 여러 주동근에 걸쳐 있어도 **한 번만** 센다. 세부 근육에서는 각각 전부 반영한다.
- **[ST-28 · 확정]** **전체 실제 완료 세트**는 근육별 중복과 무관하게 실제 완료한 세트를 한 번씩만 집계한다. 따라서 대분류·세부 근육별 세트 합계를 전체 세트와 단순 비교·합산하지 않는다.
- **[ST-29 · 확정]** 계획 외 근력 운동과 디로딩 중 실제 수행 세트도 **근육별 수행 통계**에 포함한다. 계획 세트는 해당 날짜의 적용 루틴을 기준으로 계산한다.

### 4.2 화면 구성

- **[ST-30 · 확정]** 기본 통계에는 **근육 대분류별 계획 대비 수행**을 표시하고, 선택하면 **세부 근육별 계획/실제 세트와 보조근 참여**를 확인한다.
- **[ST-31 · 확정]** 주동근과 보조근을 한 막대나 한 숫자로 합쳐서 주간 달성률을 과장하지 않는다. 주동근 기준 달성률과 보조근 참여량을 분리한다.

**예시 — 스쿼트 3세트, PRIMARY가 대퇴사두근·둔근인 경우**

| 보기 | 통계 반영 |
|---|---|
| 대퇴사두근 세부 | +3세트 |
| 둔근 세부 | +3세트 |
| 하체 대분류 | +3세트(중복 제거) |
| 전체 웨이트 완료 세트 | +3세트(중복 제거) |

## 5. 운동별·근육별 총중량과 추적

- **[ST-32 · 확정]** 운동별·근육별로 **완료 세트 수와 총중량**을 확인한다. 주간·월간 비교 모두 지원한다.
- **[ST-33 · 확정]** **총중량(kg) = Σ(각 완료 세트의 실제 사용 중량[kg] × 해당 세트의 실제 완료 반복 횟수)**. 반복 횟수를 빼고 중량만 더하지 않는다. 예: **80kg × 10회 + 80kg × 8회 + 70kg × 10회 = 2,140kg**. 세트별 실제 기록을 사용하며, 계획 반복 횟수를 대신 곱하지 않는다.
- **[ST-34 · 확정]** 이 문서의 **총중량**은 일반적으로 **볼륨 로드(중량 × 반복 횟수의 합)**라고 부르는 지표다. 별도 `세트 중량 단순 합`을 총중량으로 표기하지 않는다. 이는 승인 중량 성장 추적 지표와도 구분한다.
- **[ST-35 · 확정]** 근육별 총중량에도 주동근별 전체 반영, 대분류 동일 세트 중복 제거, 전체 운동 중복 제거 원칙을 동일하게 적용한다. 하나의 실제 세트를 같은 대분류에서 여러 번 더하지 않는다.
- **[ST-36 · 확정]** 맨몸 운동처럼 중량이 없는 경우 **총중량 항목을 표시하지 않는다**. 세트·반복은 정상 표시한다. **추가 중량이 명시적으로 기록된 경우에는 기록된 추가 중량 × 반복 횟수만 합산**하고, 체중을 임의 환산하지 않는다. 기존 기록 구조에서 추가 중량을 별도로 식별할 수 있는지 구현 시 확인한다.
- **[ST-37 · 확정]** 상세 그래프는 **세트 수 ↔ 총중량**을 선택하여 전환하는 **동일한 재사용 UI**를 운동별·근육별 화면에 적용한다. 맨몸 또는 중량 데이터가 없는 종목은 총중량 전환 항목을 숨긴다.

## 6. 운동별 성장 추적

- **[ST-38 · 확정]** 운동별 성장 추적의 **기본 그래프는 기존 승인 중량의 시간 변화**를 사용한다. 실제 수행한 중량·세트·반복 횟수는 상세 운동 기록에서 확인한다.
- **[ST-39 · 확정]** 현재 루틴에 등록된 운동만으로 제한하지 않고, **선택한 조회 기간의 전체 과거 운동 기록**에서 종목을 선택한다. 현재 루틴에서 삭제된 종목도 과거 기록이 있다면 조회 가능하다.
- **[ST-40 · 확정]** 운동 종목을 **검색으로 선택**하며 **최근 수행 종목 우선**으로 보여준다. 선택 기간에 해당하는 데이터만 그래프에 반영한다.
- **[ST-41 · 확정]** 디로딩 수행 중량은 운동 이력 및 운동량 통계에 포함하지만 **일반 중량 승인·증량·유지·감량 성과 평가 및 승인 중량 성장선에서는 제외**한다. 기존 중량 평가 체계를 새로 정의하지 않는다.
- **[ST-42 · 확정]** 승인 중량이 없거나 선택 기간에 해당 기록이 없다면 수치를 만들어내지 않고 데이터가 없음을 표시한다.

## 7. 주간·월간 운동량 추이

- **[ST-43 · 확정]** 주간 운동량은 **월~일 실제 완료 세트 합계**, 월간 운동량은 **해당 월 실제 완료 세트 합계**로 표시한다. 새 점수·정규화·피로도 추정은 하지 않는다.
- **[ST-44 · 확정]** 주간·월간 상세에서 **전체, 운동 종목별, 근육별** 실제 세트 수·총중량을 선택해 조회할 수 있다. 통합 화면에서는 요약만 제공한다.
- **[ST-45 · 확정]** 디로딩 기간이 포함된 주·월에는 그래프에 작은 **`디로딩` 표시**를 붙인다. 디로딩 중 수행 세트도 실제 통계 합계에 포함한다. 운동량 감소를 자동으로 부정적 평가하지 않는다.
- **[ST-46 · 확정]** 월마다 일수가 달라도 보정하지 않고 해당 월의 **실제 누적량**을 표시한다. 주간 평균으로 환산한 새 지표는 이번 버전의 필수 기능이 아니다.

## 8. 유산소 통계 및 마일리지

- **[ST-47 · 확정]** 유산소는 **근육별 웨이트 세트 통계에 포함하지 않고**, **운동 시간과 거리 중심의 별도 통계**로 표시한다. 단, 루틴에 포함된 유산소는 루틴 종목 달성률에는 포함한다.
- **[ST-48 · 확정]** 유산소 전체 **주간 누적 운동 시간**을 합산한다. 상세에서 월간 누적 시간도 확인할 수 있다. 계획 시간이 존재하면 **실제 시간 / 계획 시간**도 보여준다.
- **[ST-49 · 확정]** 유산소 **주간·월간 누적 거리**를 보여주되, 달리기와 실내 자전거처럼 **운동 종류별 거리로 구분**한다. 서로 다른 운동 종류의 거리를 하나의 총 km로 합쳐 성과 지표로 제시하지 않는다.
- **[ST-50 · 확정]** 직접 입력한 **실제 거리**가 있으면 그 값을 우선한다. 거리는 없지만 **실제 운동 속도와 운동 시간**을 알 수 있다면 `거리(km) = 속도(km/h) × 시간(분)/60`으로 자동 계산해 누적 마일리지에 반영한다.
- **[ST-51 · 확정]** 자동 산출 거리는 사용자가 실제 기록과 구별할 수 있도록 **`계산 거리`**로 표시하고 수정할 수 있게 한다. 수정한 거리에는 자동 계산값을 다시 덮어쓰지 않는다. 속도 또는 시간이 부족하면 거리를 억지로 추정하지 않고 시간만 반영한다.
- **[ST-52 · 확정]** 계획 외 유산소와 디로딩 유산소도 **실제 누적 시간·거리**에 포함한다. 다만 계획 외 유산소는 원본 루틴 달성률에 영향을 주지 않는다.

**예시 — 러닝머신 8km/h, 30분, 거리 미입력**

`8 × (30 ÷ 60) = 4.0km` → 운동 기록에 계산 거리 4.0km 반영. 이후 사용자가 3.8km로 수정하면 **3.8km가 우선**한다.

## 9. 날짜·이력·디로딩 연동

- **[ST-53 · 확정] 운동 날짜 귀속:** **운동 세션의 시작 시간에 해당하는 날짜**에 모든 수행 기록을 귀속한다. 자정을 넘어 종료해도 하나의 세션을 두 날짜로 분할하지 않는다. 일요일에 시작한 운동은 월요일 새벽에 끝나도 일요일 주간 통계에 들어간다.
- **[ST-54 · 확정] 시간 제한 없음:** 자정~새벽 4시 등 특정 시간대에 운동 시작·세트 기록·종료를 제한하지 않는다.
- **[ST-55 · 확정] 이력 재사용:** 통계에서 운동 내역을 누르면 기존 운동 이력 상세로 연결한다. 기존 수행 기록의 정정·삭제·복구 및 오프라인 동기화 결과를 통계에 반영한다.
- **[ST-56 · 확정] 디로딩 계획 비교:** 디로딩 중에는 **디로딩 임시 루틴의 계획 세트**를 분모로 사용한다. 디로딩이 아닌 날은 해당 날짜의 **일반 루틴 계획**을 사용한다. 한 주에 두 기간이 섞이면 각 날짜의 적용 계획을 합산한다.
- **[ST-57 · 확정] 평가 분리:** 디로딩 운동은 이력·근육별 실제 세트·월간 추이·유산소 마일리지에 포함하지만 **일반 승인 중량 변화에 대한 성과 평가에서는 제외**한다. 원본 루틴 및 승인 중량을 변경하지 않는다.

## 10. 구현 연계와 기술 확인 사항

다음은 새로운 제품 정책이 아니라 **기존 코드와 데이터 구조에 맞춰 구현 전에 검증할 항목**이다.

| 확인 항목 | 개발에서 확인할 내용 |
|---|---|
| 기존 운동 계획 | `InitialPlan`과 적용 시점별 루틴 계획 버전으로 과거 계획을 재현할 수 있는 범위. **운동을 시작하지 않은 과거 예정일**까지 당시 계획을 보존하는지 확인 필요 |
| 세트 수행 상태 | 실제 완료 세트, **세트별 실제 반복 횟수·중량**(총중량 산출), 미완료·무수행 세션, FINISHED/AUTO_CLOSED 및 사후 수정·삭제·복구 기록의 집계 기준 연결 |
| 운동 날짜 | 세션 시작 타임스탬프와 저장된 운동 날짜의 일치, 자정 넘김, 오프라인 업로드 날짜와 실제 운동 날짜 구분 |
| 표준 운동 매핑 | `standardExerciseId`, `exercise_muscle`의 `PRIMARY` / `SECONDARY`, 세부 `muscle`·`group_code`가 정확한지 검증. 중복 근육 매핑을 중복 집계하지 않도록 처리 |
| 성장 추적 | 승인 중량의 변경 이력·시점 조회 가능 여부와 현재 운동 정의/삭제된 루틴의 과거 종목 조회 확인 |
| 유산소 기록 | 실제 시간·속도·거리 단위와 저장 경로, `계산 거리`의 출처 구분, 수정 후 자동값 덮어쓰기 방지 가능 여부 |
| 맨몸·추가 중량 | `BODYWEIGHT`와 별도 추가 부하의 기록 방식. 체중을 임의로 산출하지 않고 표시 여부 결정 |
| 디로딩 연결 | 디로딩 기간 구분, 임시 루틴 계획 참조, 정상 승인 중량 평가 제외, 10일 자동 완료 후 이력 유지 |
| 조회/성능 | 주간·월간·기간별 서버 집계/API 재사용 가능성과 오프라인 미동기화 상태 UI의 표시 정확성 |

**구현 원칙:** 이미 존재하는 조회 API·운동 이력·중량 승인·오프라인 기록 흐름을 먼저 점검한다. 새 스키마·배치·별도 집계 테이블은 필요성이 실제로 확인되는 경우에만 도입한다. 이 문서는 API 명세나 구현 완료 보고서를 대체하지 않는다.
