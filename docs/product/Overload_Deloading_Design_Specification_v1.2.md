# Overload Deloading Design Specification

**버전:** v1.2  
**기준일:** 2026-11-02  
**상태:** 제품 정책 합의본 · 구현 전 (기술 검증은 별도)  
**문서 원칙:** 이 문서를 합의사항의 단일 기준으로 사용한다. 제품 정책은 합의 완료, 실제 구현은 별도이며 변경 시 규칙 ID와 변경 이력을 유지한다.

> **요약**  
> Overload의 디로딩은 피로도를 진단하거나 강제하는 기능이 아니다. 기존 **저장된 루틴**을 기준으로 적절한 시점에 짧은 회복 기간을 제안하고, 사용자가 선택한 방식에 따라 운동량을 줄여 준다. 원본 루틴 및 승인 중량은 유지하고, 디로딩 임시 루틴·이력은 독립적으로 관리한다. 권장 7일, 최대 10일이며, 10일차 종료 시 정상 완료와 동일하게 자동 종료한다.

## 0. 문서 관리 방법

- **[DOC-01 · 확정]** `v1.0` 최초 기준 문서를 발전시킨 `v1.2`를 현재 기준 문서로 사용한다. v1.1 원본은 보존한다. 이후 정책 변경 시 해당 항목의 `DL-XX` 식별자를 유지하고 문구를 수정하며 버전과 변경 이력을 갱신한다.
- **[DOC-02 · 확정]** 본문에서 **확정**은 대화에서 합의된 제품 정책, **구현 확인**은 정책은 정해졌으나 실제 코드/스키마 점검이 필요한 사항, **미결정**은 추가 판단이 필요한 사항이다.
- **[DOC-03 · 확정]** 서로 충돌한 이전 제안보다 **가장 나중에 명시적으로 합의한 정책**을 우선한다. 이 문서는 기능 구현 완료를 뜻하지 않는다.

## 1. 제품 철학 및 범위

- **[DL-01 · 확정] 루틴 우선:** 운동일 수, 계획 종목, 종목 순서, 세트·반복·중량 목표와 임시 루틴의 출발점은 기존에 저장된 원본 루틴이다. 실제 수행량으로 원본 루틴을 자동 재설계하지 않는다.
- **[DL-02 · 확정] 디로딩은 권장:** 4~8주 기준은 생리적 피로를 측정한 값이 아니라 단순한 훈련 주기 안내다. 피로 점수·주관적 강도 입력·AI 최적화는 추가하지 않는다.
- **[DL-03 · 확정] 완전 휴식 허용:** 디로딩은 운동을 해도 되고 전혀 하지 않아도 되는 회복 기간이다. 권장 운동 계획을 전부 완료할 의무가 없다.
- **[DL-04 · 확정] 독립성:** 디로딩 시작 시 원본 루틴을 참조하여 임시 루틴을 만든 이후에는 두 루틴이 서로 영향을 주지 않는다. 디로딩 중 원본 루틴 수정은 허용하지만 수행할 수 없으며, 변경 사항이 진행 중인 디로딩 임시 루틴으로 자동 전파되지 않는다.

## 2. 유효 훈련 주수 및 추천 게이지

### 2.1 분석 ON/OFF와 추천 노출

- **[DL-05 · 확정]** 분석 ON/OFF는 사용자 선택이다. OFF이면 자동 계산·게이지·알림 및 과거 기록 소급 계산이 없고, 재활성화하면 누적값 **0부터** 시작한다. 분석 OFF여도 수동 디로딩 시작과 진행 중 디로딩은 유지된다.
- **[DL-06 · 확정]** 주간 계획 운동일 수가 **2일 이상**일 때만 분석한다. 1일 이하이면 분석을 비활성 상태로 보고 게이지를 0으로 초기화한다. 다시 2일 이상이 되면 0부터 계산한다. 루틴의 주간 빈도 변경은 **다음 월요일부터** 적용한다.
- **[DL-07 · 확정]** 목표 8 유효 훈련 주를 100%로 표시한다. 4주(50%) 전에는 게이지를 숨기거나 최소 표시하고, 4~6주는 은은하게, 6~8주는 조금 더 강조한다. 8주 이상은 100%로 상한 고정한다. 팝업 강요·대형 상시 배너는 없다. 디로딩 버튼을 누르면 상세 화면으로 들어간다.

### 2.2 계산 원칙

**[DL-08 · 확정] 하루의 유효 운동일**

`유효 운동일 = 완료한 계획 종목 수 ÷ 계획 종목 수`  (하루 최대 1.0일)

- 기준은 **일반 운동 시작 시 확정한 원본 루틴의 `InitialPlan`**이다. 운동 도중 `AppliedPlan`을 수정하거나 계획 세트를 줄여도 유효 운동일 계산의 계획 종목·세트 목표는 바뀌지 않는다.
- 계획된 각 **웨이트 운동 종목은 `InitialPlan`의 계획 세트를 모두 수행**해야 1개 완료로 인정한다. 4세트 계획 중 3세트 수행이면 그 종목의 완료값은 0이다.
- **유산소도 `InitialPlan`에 담긴 기존 루틴의 목표를 달성**해야 1개 완료로 인정한다. 시간·속도 등 실제 등록된 목표만 비교한다. 운동 도중 목표를 낮춰도 최초 계획 기준을 유지한다.
- 원본 루틴에 없는 추가 운동·추가 유산소는 기록 및 통계에는 남지만 분자에 포함하지 않는다. 루틴에 계획된 유산소는 웨이트와 같은 규칙으로 포함한다.
- 하루에 여러 운동 기록이 있어도 계획된 하루의 유효 운동일은 최대 1이다. 실제 수행 기록은 계획 이행 확인에만 사용한다.

**[DL-09 · 확정] 월~일 유효 훈련 주수**

`한 주의 유효 훈련 주수 = min(1, 월~일 유효 운동일 합계 ÷ 그 주에 적용되는 원본 루틴의 계획 운동일 수)`

- 예: 계획 주 4일, 일별 유효 운동일 1.0 / 0.6 / 1.0 / 0.5 → `3.1 ÷ 4 = 0.775주`.
- **[DL-10 · 확정]** 월~일 한 주가 완전히 끝났을 때 그 주의 **유효 운동일 합계가 0**이면 누적 주수를 0으로 초기화한다. 이는 '실제 운동을 전혀 하지 않음'과 다를 수 있다. 예를 들어 부분 세트만 수행한 주도 완료 종목이 하나도 없으면 이 규칙을 따른다. 별도 예외를 만들지 않는다.
- **[DL-11 · 확정]** 계획 운동일 수가 2일 이상인 범위에서 빈도만 바뀌면 이전 누적 주수는 유지하고 새 분모는 **다음 월요일**부터 사용한다. 세트·운동 종목 변경은 주간 계획 운동일 수를 자동 변경하지 않는다.
- **[DL-12 · 확정]** 디로딩 기간 중에는 유효 주수 누적과 주간 0일 초기화 판정을 일시 정지한다. 정상 완료·자동 완료 시 누적값 0, 실제 수행 없이 취소할 때 이전 누적값을 유지한다. 취소 뒤 디로딩이 포함된 주의 0일 초기화를 소급 적용하지 않는다.
- **[DL-13 · 확정]** 디로딩 완료 **다음 날부터** 일반 운동을 할 수 있다. 해당 날짜가 기존 월~일 주 안에 남아 있다면, 남은 날들의 정상 운동 기록을 그 주의 전체 계획 운동일 수로 나누어 계산한다. 디로딩 일수만큼 분모를 줄이거나 다음 월요일까지 계산을 유예하지 않는다.
- **[DL-14 · 확정/구현 확인]** `InitialPlan`과 현재 유효한 실제 수행 기록을 비교하여, 서버 동기화 및 기록 정정·삭제·복구 이후 유효 주수를 재계산할 수 있도록 한다. 오프라인에서 실제 운동한 날짜를 사용하고 업로드 날짜는 사용하지 않는다. 동기화 전 서버 표시는 일시적으로 과소 평가될 수 있다.

### 2.3 계산 예시

| 주간 계획 | 실제 계획 종목 완료 | 유효 운동일 | 결과 |
|---|---|---:|---:|
| 주 4일, 하루 5종목 | 첫날 5/5, 둘째 3/5, 셋째 4/4, 넷째 2/4 | 1 + 0.6 + 1 + 0.5 = 3.1 | 0.775주 |
| 주 4일 | 4일 모두 세트 일부만 수행, 완료 종목 0 | 0 | 주가 끝나면 누적 0으로 초기화 |
| 디로딩을 수요일에 완료한 주 6일 계획 | 목·금·일 정상 운동일 각각 1.0 | 3.0 | 0.5주 |

## 3. 디로딩 시작·취소·완료·자동 종료

- **[DL-15 · 확정] 시작 제한:** 진행 중인 일반 세션이 없어야 하며, **오늘 실제 운동 수행 기록이 하나라도 있으면** 디로딩을 오늘 시작할 수 없다. 계획 내 웨이트뿐 아니라 추가 유산소, 오프라인 미동기화 수행 기록도 포함한다.
- **[DL-16 · 확정] 무수행 세션:** 시작만 하고 웨이트 세트·유산소 수행이 전혀 없는 세션은 취소 시 운동 이력으로 남기지 않고 정리한다. 오프라인 미동기화 수행을 잘못 삭제하지 않아야 한다. 실제 수행이 하나라도 있으면 해당 사실을 보존한다.
- **[DL-17 · 확정] 진행 중 구분:** 일반 운동과 디로딩 운동을 동시에 진행할 수 없다. 진행 중인 세션을 다른 유형으로 변경하거나 앱이 임의로 종료하지 않는다. 디로딩 중 원본 루틴은 수정 가능하나 실행 불가다.
- **[DL-18 · 확정] 기간:** 시작일을 1일차로 하는 **권장 7일**. 8·9·10일차까지 연장되며 **10일차의 종료 시점에 자동 정상 완료**한다. 11일차부터 원본 루틴을 다시 실행할 수 있다. 7일차에 자동 종료하지 않는다.
- **[DL-19 · 확정] 직접 완료:** 사용자는 7일을 채우지 않았거나 운동을 전혀 하지 않았어도 언제든 완료를 선택할 수 있다. 완료한 **당일까지 디로딩 기간**이며 그날 일반 운동으로 전환하지 않는다. 완료 시 누적 유효 주수는 0, 운동/디로딩 이력은 보존, 임시 루틴은 비활성화한다.
- **[DL-20 · 확정] 취소:** 디로딩 운동을 **한 번도 실제 수행하지 않았을 때만** 취소할 수 있다. 완전 휴식으로 며칠을 보낸 경우에도 실제 수행이 없으면 취소 가능하다. 웨이트 1세트 또는 유산소의 실제 수행이 한 번이라도 있으면 취소 불가이며 완료로 종료한다. 취소 시 누적 유효 주수 유지.
- **[DL-21 · 확정] 방식 변경:** 3일형↔2일형↔휴식 등 디로딩 방식 교체는 실제 수행 **전까지만** 가능하다. 0세트 세션을 취소·정리했다면 변경 가능. 수행 후에는 방식 고정; 미수행 운동의 일정/종목/중량 등 임시 루틴 수정은 계속 허용한다.
- **[DL-22 · 확정] 자동 완료:** 10일차 종료 시 사용자 직접 완료와 **동일한 상태 전이 및 효과**를 적용한다. 별도의 확인창은 없고, 11일차 일반 루틴으로 돌아간다.

## 4. 선택 가능한 디로딩 방식

**[DL-23 · 확정] 기존 루틴의 주간 운동일 수를 넘는 압축형은 제공하지 않는다.**

| 기존 주간 운동일 | 선택 가능한 방식 (완전 휴식 공통) |
|---|---|
| 주 6일 | 기존 6일 유지 / 주 3회 운동형 / 주 2회 운동형 / 완전 휴식 |
| 주 5일 | 기존 5일 유지 / 주 3회 운동형 / 주 2회 운동형 / 완전 휴식 |
| 주 4일 | 기존 4일 유지 / 주 3회 운동형 / 주 2회 운동형 / 완전 휴식 |
| 주 3일 | 기존 3일 유지 / 주 2회 운동형 / 완전 휴식 |
| 주 2일 | 기존 2일 유지 / 완전 휴식 |

- **[DL-24 · 확정] 기존 루틴 유지:** 기존 운동 요일·분할·운동 종목을 유지한 상태에서 디로딩 중량/세트/반복/유산소 목표만 낮춘다. 기존 루틴에서 여러 날 반복되는 같은 운동도 그대로 유지할 수 있다.
- **[DL-25 · 확정] 주 3회 압축:** 등록 운동을 Push / Pull / Legs로 분리할 수 있으면 그 구조로 생성한다. 어느 한 영역이 비어 정상 분할이 불가능하면 **3일 균등 분배**로 대체하며 3일형 선택 자체를 막지 않는다.
- **[DL-26 · 확정] 주 2회 압축:** 전면 / 후면 분리가 가능하면 그 구조로 생성한다. 불가능하면 **2일 균등 분배**로 대체한다.
- **[DL-27 · 확정] 완전 휴식:** 운동 루틴을 생성하지 않고 휴식 기간만 관리한다. 운동 0회여도 정상 완료할 수 있다.
- **[DL-28 · 확정]** 주 3일·2일형의 가능 여부는 **원본 루틴의 계획 운동일 수**로만 판단한다. 특정 분할이나 운동 종목 수가 부족하다는 이유로 선택을 추가 제한하지 않는다. 원본에 없는 운동은 절대 자동 추가하지 않는다.

### 4.1 분할별 근육 구분

| 분할 | 포함되는 대표 영역 |
|---|---|
| Push | 가슴, 전면·측면 어깨, 삼두 |
| Pull | 등, 후면 어깨, 이두 |
| Legs | 대퇴사두근, 햄스트링, 둔근, 종아리 |
| 전면 | 가슴, 전면·측면 어깨, 삼두, 대퇴사두근, 복근 |
| 후면 | 등, 후면 어깨, 이두, 햄스트링, 둔근, 종아리 |

※ 이 구분은 자동 편성 기준이다. 하나의 운동이 여러 `PRIMARY` 근육을 가질 수 있으며, 복합 운동은 더 적절한 **한 날짜에만** 배치한다.

## 5. 운동 종목 자동 선정 및 정렬

- **[DL-29 · 확정] 출처 제한:** 원본 주간 루틴에 실제 등록되어 있는 표준 운동만 사용한다. 비어 있는 분할을 채우기 위해 새 운동을 발명하거나 외부 추천을 추가하지 않는다.
- **[DL-30 · 확정] 대표 운동 선정:** `exercise_muscle`의 세부 `PRIMARY` 근육을 기준으로 아직 포함되지 않은 근육의 대표 운동을 우선한다. 일반 가슴과 윗가슴처럼 서로 다른 세부 PRIMARY라면 모두 고려할 수 있다. `SECONDARY`만으로 PRIMARY 커버를 대체하지 않는다.
- **[DL-31 · 확정] 메인 우선:** 같은 주동근의 운동 후보에서는 원본 루틴에서 **먼저 배치된 운동**을 우선한다. 세트 수나 반복 수가 많다는 이유로 보조 운동을 메인보다 우선하지 않는다.
- **[DL-32 · 확정] 다관절 우선 정렬:** 주동근 커버를 고려해 종목을 선정한 뒤 **다관절(COMPOUND) → 단관절(ISOLATION)** 순서로 정렬한다. 같은 분류 안에서는 기존 루틴의 우선순위를 유지한다. 다관절이라는 이유만으로 동일 PRIMARY의 중복 운동을 무조건 선정하지 않는다.
- **[DL-33 · 확정] 다중 PRIMARY:** 한 운동이 대퇴사두근·둔근 등 여러 PRIMARY를 가지면 선택 시 해당 근육을 모두 커버한 것으로 본다. 서로 다른 분할에 걸쳐도 가장 적절한 한 날에만 배치하고, 다른 날에 동일한 웨이트 종목을 재배치하지 않는다.
- **[DL-34 · 확정] 3일형 분할의 순서:** 기존 주간 루틴의 요일별 **첫 메인 운동**을 원본 요일 순서로 보며, Push·Pull·Legs의 최초 등장 순서대로 3일형 순서를 정한다. 중복 분할은 건너뛴다. 예: 등·등·가슴·하체·가슴·하체 → Pull·Push·Legs.
- **[DL-35 · 확정] 균등 분배 대안:** 정규 분할이 안 되면 선정된 메인 운동부터 **1일차→2일차(→3일차)→1일차…** 라운드로빈 배치한다. A·B·C·D 우선순위의 2일형은 `A,C` / `B,D`다. `A,B` / `C,D`처럼 뒤쪽 날에 보조 운동만 몰아넣지 않는다.
- **[DL-36 · 확정] 커버와 운동량의 균형:** 부위별 대표성을 확보하되 하루 종목·세트 상한을 넘기지 않는다. 상한을 채우려고 종목을 억지로 추가하지 않는다. 선택 이후 사용자가 임시 루틴을 수정할 수 있다.

### 5.1 예시: 원본 주 6일의 Push 통합

| 원본 월요일 Push | 원본 목요일 Push |
|---|---|
| 벤치프레스(가슴) | 인클라인 벤치프레스(윗가슴) |
| 숄더프레스(전면 어깨) | 사이드 레터럴 레이즈(측면 어깨) |
| 트라이셉스 익스텐션(삼두) | 체스트 플라이(가슴) |

**추천 Push:** ① 벤치프레스 → ② 인클라인 벤치프레스 → ③ 숄더프레스 → ④ 사이드 레터럴 레이즈 → ⑤ 트라이셉스 익스텐션. 같은 세부 PRIMARY를 이미 대표하는 체스트 플라이는 우선순위가 낮아진다. 실제 결과는 표준 운동별 정확한 PRIMARY 매핑과 상한에 따라 달라진다.

### 5.2 표준 운동 데이터 보강

- **[DL-37 · 확정]** `standard_exercise`에 **다관절/단관절 분류값 `jointType`**을 추가하는 방향이다. 후보값은 `COMPOUND`, `ISOLATION`, `OTHER`(유산소 등 해당 없음). 단지 PRIMARY/SECONDARY 개수로 다관절 여부를 추측하지 않는다.
- **[DL-38 · 확정]** 별도 `LARGE`/`SMALL`(큰 근육·작은 근육) 구분은 지금 추가하지 않는다. 이미 있는 세부 PRIMARY, 원본 메인 순서, `jointType`으로 판단한다.
- **[DL-39 · 구현 확인]** 표준 운동의 세부 PRIMARY 매핑과 `jointType`을 정확히 채우고 검증해야 한다. 현재 예시용 운동/근육 데이터가 실제 제품의 모든 운동 분류를 대표하지는 않는다.

## 6. 웨이트 운동량 감량

- **[DL-40 · 확정] 중량:** 승인 중량이 있으면 그 값을, 없으면 원본 루틴에 설정된 초기 중량을 기준으로 **85%** 적용한다. **PLATE·STACK = 5kg, DUMBBELL = 2kg, 장비 구분 없음 = 1kg** 단위로 **내림**한다. BODYWEIGHT는 중량 조절 없이 세트·반복으로 조절한다.
- **[DL-41 · 확정] 0kg 방지:** 소중량 운동에서 장비 단위 내림으로 0kg가 되면 0kg로 만들지 말고 원래 소중량을 유지한 채 세트·반복을 줄인다. 장비 단위 탓에 중량 감량폭이 커지면 반복까지 과도하게 중복 감량하지 않도록 한다.
- **[DL-42 · 확정] 세트:** 기존 세트 수의 **50%를 정수 반올림(0.5는 올림)**하고 **최소 1세트** 유지한다. 예: 1→1, 2→1, 3→2, 4→2, 5→3, 6→3.
- **[DL-43 · 확정] 반복:** **짝수 세트**는 세트만 절반으로 줄여 반복 횟수를 기본 유지한다. **홀수 세트**는 세트를 반올림한 뒤 **반복 횟수를 낮춰 전체 수행 횟수가 약 50%**가 되도록 보정한다. 정확한 50%는 의무가 아니다. 예: 3×10→2×8(약 53%), 5×10→3×8(48%), 3×8→2×6(50%), 1×10→1×5.
- **[DL-44 · 확정] 압축형 종목 상한:** 주 3일형은 `min(원본 루틴 하루 평균 웨이트 종목 수 + 1, 6)`을 상한으로, 주 2일형은 `min(평균 + 2, 7)`을 상한으로 삼는다. 평균이 정수가 아닐 때 최종 정수화 방법은 구현 전 확인 항목이다. **상한은 목표 종목 수가 아니다.**
- **[DL-45 · 확정] 압축형 세트 상한:** 하루 전체 계획 세트는 원본 루틴의 하루 평균 세트 수의 **약 70%를 넘기지 않는 방향**으로 조정한다. 주간 총세트의 절반은 참고치이고, 압축형에서 약 20~40%로 줄어도 무방하다. 당일 운동이 원래보다 과중해지지 않는 것이 우선이다.
- **[DL-46 · 확정] 자동 적용 시점:** 감량은 임시 루틴을 **최초 생성할 때만** 적용한다. 이후 사용자가 수정한 중량·세트·반복은 자동으로 덮어쓰지 않는다. 실제 운동 수행 전 방식 변경으로 새 루틴을 다시 생성하는 경우에만 새 추천값을 적용한다.

### 6.1 세트·반복 예시

| 원본 세트 × 반복 | 디로딩 세트 × 반복 | 총 반복 비율 |
|---|---|---:|
| 4 × 10 | 2 × 10 | 50% |
| 6 × 10 | 3 × 10 | 50% |
| 3 × 10 | 2 × 8 | 약 53% |
| 5 × 10 | 3 × 8 | 48% |
| 1 × 10 | 1 × 5 | 50% |

## 7. 유산소 자동 편성과 감량

- **[DL-47 · 확정]** 기존 루틴에 등록된 유산소만 디로딩에 포함한다. 계획에 없던 종목을 자동 추가하지 않는다. 유산소를 포함해도 수행 여부는 사용자 선택이다.
- **[DL-48 · 확정] 목표:** 등록된 **속도는 85%**로 줄이고 **소수점 첫째 자리**까지 반올림한다(예: 7.5km/h→6.4km/h). **시간은 50%**로 줄이고 **1분 단위 반올림(0.5분 올림)**한다(35분→18분, 45분→23분). 속도가 없으면 시간만 감량하고 없는 목표는 새로 만들지 않는다.
- **[DL-49 · 확정] 기존 루틴 유지:** 유산소 요일/종목 구성은 원본 그대로 두고 해당 목표만 낮춘다.
- **[DL-50 · 확정] 압축형 하루 상한:** 유산소는 웨이트 종목 수와 **별개**로 하루 **최대 1종목**이다. 원본 주간 루틴에 여러 종류가 있으면 **먼저 등록된 유산소**를 기본 추천하며 사용자가 변경할 수 있다.
- **[DL-51 · 확정] 3일형:** 원본 유산소가 주 **2일 이상**이면 Legs를 제외한 두 분할일에 유산소 1종목씩 배치한다. 원본 유산소가 주 **1일**이면 하체가 아닌 **첫 운동일**에만 배치, **0일**이면 추가하지 않는다.
  - **Legs 구분이 없는 3일 균등 분배 대안:** 원본 유산소가 주 **1일**이면 **첫 운동일**, 주 **2일 이상**이면 **앞의 두 운동일**에 하루 1종목씩 배치한다. 원본 유산소가 **0일**이면 추가하지 않는다. 원본에 등록된 유산소만 사용하며 DL-50의 하루 상한·우선 종목과 DL-53의 유산소 중복 예외를 유지한다. 이 예외는 Legs 구분이 없는 3일 균등형에만 적용한다.
- **[DL-52 · 확정] 2일형:** 원본 유산소가 주 **2일 이상**이면 두 운동일 모두 배치, **1일**이면 첫 운동일에만 배치, **0일**이면 추가하지 않는다.
- **[DL-53 · 확정] 중복 예외:** 압축형에서 **웨이트 종목은 서로 다른 날짜에 중복 선정하지 않지만**, 유산소는 위 배치 규칙에 따라 동일 종목이 여러 날짜에 한 번씩 나타날 수 있다.

## 8. 요일 자동 배치·수정·연장

- **[DL-54 · 확정]** 기존 루틴 유지형은 **원본 운동 요일**을 따른다.
- **[DL-55 · 확정]** 3일형은 **시작일 / 시작일+2 / 시작일+4**, 2일형은 **시작일 / 시작일+3**으로 최초 제안한다. 예: 월요일 시작 → 3일형 월·수·금, 2일형 월·목. 7일은 월~일 고정이 아닌 **실제 시작일부터 7일**이다.
- **[DL-56 · 확정]** 사용자는 권장 7일 안에서 미수행 운동의 날짜를 자유롭게 변경할 수 있고 **연속된 운동일도 허용**한다. 자동 추천은 처음 한 번이며 사용자가 수정한 날짜는 자동 재배치하지 않는다.
- **[DL-57 · 확정]** 이미 수행한 날짜·실제 기록은 고정한다. **미수행 운동만** 날짜를 바꿀 수 있다. 놓친 운동도 앱이 자동 완료·삭제·이동하지 않고 사용자가 직접 수정한다.
- **[DL-58 · 확정]** 디로딩 도중 방식 변경은 수행 전이라는 조건뿐 아니라 **남은 기간 내 실제 배치 가능한 운동일 수**도 고려한다. 남은 날짜가 3일이면 최대 3회형, 2일이면 최대 2회형, 1일이면 새 자동 생성을 권장하지 않고 종료를 안내한다. **7일이 지난 뒤에는 새 디로딩 루틴을 자동 생성하지 않는다.**
- **[DL-59 · 확정]** 8~10일차까지 이어지면 메인 하단 루틴 UI는 새로운 주차처럼 이동하고 **8일차·9일차·10일차**를 표시한다. **미수행 운동을 8~10일차로 이동하거나 기존 임시 루틴을 수정하는 것은 가능**하지만, **새 디로딩 루틴의 생성은 불가**하다. 완료된 운동의 날짜·실적은 고정한다. 10일차 종료 후 자동 완료.

## 9. 화면 및 사용자 흐름

- **[DL-60 · 확정] 진입:** **디로딩 버튼 → 상세 화면 → 방식 선택 → 자동 루틴 미리보기 → 시작 확정**. 추천 분석 OFF여도 수동 진입 가능하다. 수동 시작을 별도의 '루틴 관리 메뉴'로 옮기는 제안은 채택하지 않았다.
- **[DL-61 · 확정] 미리보기:** 기존 요일별 루틴 UI를 재활용한다. 첫 화면은 전체 7일 일정, 원하는 날짜를 펼치면 운동 종목·중량·세트·반복을 확인한다. **시작 전에는 미리보기 중심**, 세부 수정은 시작 후 기존 임시 루틴 편집 기능으로 진행한다.
- **[DL-62 · 확정] 메인 하단:** 일반 훈련 시 원래 **월~일 주간 루틴**을, 디로딩 시 **시작일부터 7일간의 임시 루틴**을 표시한다. 완전 휴식은 휴식 일정으로 표현한다. 8~10일차는 새로운 주차 화면으로 이동한다. 일반 루틴과 디로딩 루틴을 동시에 보여주지 않는다.
- **[DL-63 · 확정] 진행 표시:** 디로딩 진행 중에는 기존 유효 주수 추천 게이지를 숨기고, **진행 일차·남은 권장 일수** 정도만 간단히 보여준다. 기간을 넘기면 '권장 기간 경과'와 8~10일차를 표시한다.
- **[DL-64 · 확정] 종료 컨트롤:** 메인에는 상태만 표시한다. 디로딩 상세 화면에 **완료** 및 수행 전인 경우 **취소**를 둔다. 각 버튼은 **확인창 한 번**을 거친다. 완료에는 누적 주수 초기화·기록 보존·다음 날 복귀를 안내한다. 10일차 자동 완료는 확인창 없이 처리한다.

## 10. 운동 이력, 통계, 원본 루틴 보호

- **[DL-65 · 확정]** 디로딩 중 수행한 세트·중량·유산소의 실제 기록은 정상 운동 이력에 남기고 **디로딩 운동임을 구분**한다. 수행 당시의 운동 계획(스냅샷)도 유지한다. 나중에 임시 루틴을 수정해도 과거 수행 기록은 바뀌지 않는다.
- **[DL-66 · 확정]** 디로딩 실적은 **근육별 주간 통계와 운동 이력에 포함**한다. 그러나 일반 중량 **증량·유지·감량 평가 및 승인 중량 변경**에서는 제외한다. 디로딩 중 수동 중량/세트 조정도 일반 성과 평가에 반영하지 않는다.
- **[DL-67 · 확정]** 완료 후 임시 루틴은 **비활성화하여 일반 루틴 목록에 노출하지 않음**. 수행 세션의 기록과 당시 계획, 디로딩 시작/종료 날짜·방식은 조회할 수 있게 보존한다. 완전 휴식으로 운동 기록이 0건이어도 디로딩 자체 이력은 남긴다.
- **[DL-68 · 구현 확인]** 기존 `InitialPlan`·`AppliedPlan`, 운동 세트의 장비/중량 스냅샷, FINISH/AUTO_CLOSED, 사후 수정·삭제·복구, 오프라인 IndexedDB 및 서버 동기화 흐름을 재사용한다. 일상 운동과 디로딩 세션에 동일한 단일 활성 세션 원칙을 적용한다.

## 11. 제품 정책 합의 완료 및 구현 검증 항목

**제품 정책에 관한 추가 의사결정은 이번 논의에서 마무리했다.** 다음 항목은 기존 합의를 다시 여는 질문이 아니라, 실제 코드·데이터·시뮬레이션으로 확인하거나 구현 과정에서 조심해야 하는 **기술적 검증 사항**이다. 사용자에게 새 입력을 요구하지 않으며, 정책과 충돌이 발견될 때만 다시 논의한다.

| ID | 구분 | 검증 내용 | 기준/주의점 |
|---|---|---|---|
| CHECK-01 | 적용 확인 | `InitialPlan`과 실제 완료 세트·유산소 목표 비교 | **해결된 정책:** 운동 중 계획 수정과 무관하게 최초 원본 루틴 기준으로 계산 |
| CHECK-02 | 화면·저장 | 8~10일차 기존 운동의 이동 및 수정 | **해결된 정책:** 미수행 이동 가능, 새 루틴 생성 불가, 완료 기록 고정 |
| CHECK-03 | 자동 편성 검증 | 주동근 커버·메인 우선·다관절 정렬·균등 분배·일일 상한이 동시에 적용되는지 | 실제 2~6일 원본 루틴 여러 개로 예상 결과를 비교 |
| CHECK-04 | 수치 경계 | 평균 웨이트 종목 수와 평균 세트 상한의 정수화 | 상한을 초과하지 않고 신규 종목을 채우지 않도록 구현 방식 검증 |
| CHECK-05 | 수치 경계 | 세트별 반복 수가 서로 다를 때 홀수 세트 반복 보정 | **원칙은 확정:** 총 수행 횟수 약 50%, 정수 세트·반복, 무리한 추가 감량 방지 |
| CHECK-06 | 카탈로그 | `jointType` 추가와 세부 `PRIMARY` 근육 매핑 품질 | 다관절 여부를 근육 개수로 추측하지 않음; 카탈로그 정비 필요 |
| CHECK-07 | 기록·동기화 | 무수행 세션 정리, 오프라인 미동기화, 과거 기록 정정, 10일차 자동 완료 | 원본 기록 유실·이중 세션·날짜 오류·중량 평가 유입 방지 |
| CHECK-08 | 정책 확정·구현 검증 대기 | Legs 구분이 없는 3일 **균등 분배 대안**의 유산소 자리 | 2026-11-02 사용자 확정: 원본 주 1일이면 첫 운동일, 주 2일 이상이면 앞의 두 운동일에 하루 1종목씩. 원본 주 0일이면 추가 없음. DL-50·51·53과 아래 수용 테스트로 검증 |

> **검증 원칙:** 위 사항을 이유로 이미 확정된 제품 정책(루틴 독립성, 압축형 웨이트 중복 금지, 10일 자동 완료, 유효 주수 규칙, 유산소 통계 포함 등)을 임의로 변경하지 않는다. CHECK-08의 배치 예외는 v1.2에서 사용자 결정으로 확정했으며, 실제 자동 편성 구현과 검증은 별도다.

## 12. 핵심 수용 테스트 (예상 결과)

## 13. 이전 제안 중 폐기·변경된 사항

- 주 3회 압축에서 Push → Pull → Legs **고정 순서** 제안 → **원본 요일별 첫 메인 운동의 분할 최초 등장 순서**로 변경.
- 특정 부위가 없으면 주 3일/주 2일 방식을 **선택 불가** 제안 → **균등 분배 대안**으로 변경. 가능한 방식 수는 원본 주간 운동일로만 제한.
- 운동 후보를 단순히 `A,B | C,D`로 묶는 방식 → 메인 균형을 위해 **`A,C | B,D` 라운드로빈**으로 변경.
- 디로딩 중 7일 경과 후 계속 진행하되 **자동 종료 없음** → **최대 10일, 10일차 종료 시 자동 정상 완료**로 변경.
- 유산소를 2·3일 압축형에서 **제외**한다는 제안 → **포함**, 감량·배치 기준 확정.
- **반복 횟수는 항상 유지** 제안 → 홀수 세트에서는 **반복 횟수 보정**으로 수정.
- 디로딩 **수동 시작을 루틴 관리 메뉴로 이동**한다는 제안 → **디로딩 버튼의 상세 화면**에서 시작.
- 디로딩을 수행한 후에도 **취소 가능** 제안 → 실제 수행 후 **취소 불가**, 완료만 가능.
